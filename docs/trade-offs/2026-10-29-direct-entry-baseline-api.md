# 대기열 적용 전 기준선을 위한 직접 입장 API

## 선택지

- 대기열 on/off 설정 프로퍼티로 같은 API의 동작을 바꾼다
- 기준선 전용 엔드포인트(`POST /entries/direct`)를 따로 둔다
- 기준선 시나리오에서 토큰 검증 자체를 끈다

## 선택

`POST /api/v1/events/{eventId}/entries/direct`가 대기열 없이 즉시 Redis 토큰을 발급한다. 좌석 선점 API와 토큰 검증은 그대로 쓴다.

## 이유

- 설정으로 바꾸면 전/후를 비교할 때마다 앱을 재시작해야 하고, 같은 앱에서 두 시나리오를 번갈아 돌릴 수 없다.
- 토큰 검증을 끄면 선점 경로가 달라져서 공정한 비교가 아니다. 직접 입장도 같은 토큰으로 같은 선점 API를 타므로 차이는 "대기열 유무"만 남는다.
- 감수한 점: 운영이라면 대기열을 우회하는 경로가 되므로 노출하면 안 된다. 시뮬레이터의 목적(전/후 비교)상 남겨 두고, 배포 시 비활성화 대상으로 기록한다.
