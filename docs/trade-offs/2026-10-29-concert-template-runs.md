# 사용자 입력 이벤트 생성 → 공연 템플릿 + 회차 방식

## 선택지

- 기존처럼 사용자가 이벤트명/좌석 수/오픈 시각을 입력 (좌석 수 상한만 추가)
- 공연 10개를 DB에 두고 모든 사용자가 같은 공연을 공유 (주기적 리셋 필요)
- 공연 10개를 템플릿으로 두고, 고를 때마다 새 회차(Event)를 생성

## 선택

템플릿 + 회차 방식. 공연 목록은 백엔드 시드 데이터이고, `POST /concerts/{id}/runs`가 서버가 정한 좌석 수로 회차를 만든다.

## 이유

- 사용자가 좌석 수를 정하면 5000석, 수십만 석처럼 로컬 PC가 감당하지 못하는 요청이 들어올 수 있다. 프론트에서만 막으면 API로 우회되므로, 서버가 템플릿 ID만 받고 좌석 수를 스스로 정하게 했다. 기존 이벤트 생성 API에도 `@Max(500)`을 넣었다.
- 공유 방식은 앞사람이 팔아 둔 좌석이 남아 체험이 매번 달라지고, 리셋 시점/리셋 중 결제 처리 같은 핵심과 무관한 문제가 생긴다. 회차 방식은 항상 빈 좌석에서 시작한다.
- 다른 관객과의 경쟁은 k6 가상 관객으로 만든다. 화면에 회차 번호를 보여 주고 `EVENT_ID`로 같은 회차에 부하를 보낼 수 있게 했다.
- 감수한 점: 회차와 좌석 행이 계속 쌓인다(회차당 최대 500행). 필요해지면 오래된 회차 정리 스케줄러를 붙인다.
