# 프론트엔드: 단계 상태 관리와 개발 프록시

## 선택지

- 화면 전환: React Router 도입 vs `App`의 단계(step) 상태 하나로 전환
- 백엔드 연동: 백엔드에 CORS 허용 설정 추가 vs Vite 개발 서버 프록시(`/api`, `/ws`)

## 선택

- 라우터 없이 `setup → waiting → seats → payment → result` 단계를 discriminated union 상태로 관리한다.
- Vite 프록시로 같은 origin처럼 호출해서 백엔드 CORS 설정을 추가하지 않는다. STOMP는 `@stomp/stompjs`로 네이티브 WebSocket만 쓴다(SockJS 미사용).

## 이유

- 흐름이 한 방향이고 각 단계가 앞 단계의 결과(이벤트, 입장 토큰, 선점 좌석)를 반드시 필요로 한다. URL로 중간 단계에 직접 들어오는 경우가 없어서, 라우터를 쓰면 상태 복원 코드만 늘어난다. 감수한 점: 새로고침하면 처음부터 다시 시작한다.
- 프록시는 개발 환경 설정만으로 끝나고 백엔드 보안 설정을 건드리지 않는다. 배포 시에는 같은 도메인 리버스 프록시나 CORS 설정이 필요하다.
- 결제 타이머는 서버의 선점 시각이 응답에 없어서 선점 응답을 받은 시점부터 센다. 실제 만료와 수 초 차이가 날 수 있다.
- 대기 화면은 WebSocket 알림을 받으면 토큰을 조회하고, 구독 전에 이미 허용된 경우를 놓치지 않도록 2초마다 상태도 확인한다.
