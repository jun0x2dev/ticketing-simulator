# 모니터링: Prometheus 수집 + Grafana 대시보드, 대기열 지표는 직접 정의

## 선택지

1. **지표 수집 방식**
   - Prometheus가 앱의 `/actuator/prometheus`를 주기적으로 가져가는 방식(pull)
   - 앱이 수집 서버로 지표를 밀어 넣는 방식(push, 예: OTLP)
2. **대기 인원 지표**
   - 접수/허용/실패 카운터를 앱에서 세고, 대시보드에서 `접수 - 허용 - 실패`로 계산
   - 지표를 수집할 때마다 Redis 대기 줄(`queue:line:*`)의 크기를 읽는 게이지
3. **대기 시간 분위수**
   - 앱이 p95를 직접 계산해 내보내기
   - 히스토그램 버킷을 내보내고 Prometheus에서 `histogram_quantile`로 계산
4. **모니터링 컨테이너 실행 시점**
   - 기본 `docker compose up`에 항상 포함
   - compose 프로필(`monitoring`)로 필요할 때만 실행

## 선택

- **수집 방식:** pull 방식을 쓴다(Micrometer + actuator + Prometheus).
- **대기 인원:** Redis 대기 줄을 SCAN으로 훑어 크기를 합산하는 게이지를 쓴다.
- **대기 시간:** 접수 시각(`requestedAt`)부터 입장 허용까지를 타이머로 잰다. 히스토그램 버킷 범위는 100ms~10분으로 둔다.
- **HTTP 응답 시간:** 히스토그램 버킷으로 내보낸다.
- **실행 시점:** Prometheus와 Grafana는 `monitoring` 프로필로만 띄운다. 대시보드와 데이터소스는 파일로 프로비저닝한다.

## 이유

- **pull 방식**
  - Spring Boot가 기본 지원하는 방식이라, 의존성 두 개와 설정 몇 줄이면 된다.
  - 앱이 죽으면 수집이 끊겨 "앱이 응답하지 않음"이 그래프의 빈 구간으로 바로 보인다.
  - push 방식은 수집기(OTel Collector 등)를 하나 더 운영해야 해서, 로컬 시뮬레이터 규모에 비해 크다.
- **대기 인원 게이지**
  - 카운터로 계산하면 앱이 재시작될 때마다 값이 0으로 돌아가 차이가 틀어진다.
  - 서버를 여러 대로 늘리면 서버마다 접수와 허용이 따로 세어져 맞추기 어렵다.
  - Redis 줄은 이미 순번 계산의 기준이라, 그 크기를 그대로 읽는 쪽이 사용자가 보는 순번과 항상 맞는다.
  - 서버가 여러 대면 각자 같은 값을 내므로 대시보드에서는 `max`로 읽는다.
  - 감수한 것: 수집 주기(5초)마다 SCAN과 ZCARD가 실행된다. 회차 줄은 1시간 TTL로 정리되어 키 수가 적고, SCAN은 Redis를 막지 않아 부담이 작다.
- **실제 대기 시간 타이머**
  - 대기 화면의 예상 대기 시간은 설정값(`queue.worker.tps`)으로 계산한다. 실제 입장 속도가 그보다 느리면 사용자는 안내보다 오래 기다린다.
  - 실제로 대기 화면은 "약 3초"로 안내했는데, 부하 중에는 48초를 기다린 사례가 있었다.
  - 접수 시각부터 잰 실제 대기 시간과 초당 입장 수를 따로 봐야 이 차이가 드러난다.
  - DLT 재투입을 거친 요청도 처음 접수 시각부터 재므로, 사용자가 실제로 기다린 시간이 된다.
- **히스토그램 버킷**
  - 앱이 직접 계산한 p95는 서버 여러 대의 값을 합칠 수 없다. 버킷은 더해서 다시 계산할 수 있다.
  - 타이머 기본 버킷의 상한은 30초다. 대기열은 몇 분씩 밀릴 수 있어서 상한을 10분으로 넓혔다. 그대로 두면 30초를 넘는 대기가 모두 `+Inf` 하나로 뭉쳐 분위수가 틀어진다.
- **monitoring 프로필**
  - 부하 테스트를 하지 않을 때는 컨테이너 두 개를 아낄 수 있다.
  - 대시보드를 JSON 파일로 프로비저닝해, `up` 한 번이면 같은 화면이 뜬다.
- **노출 범위**
  - actuator는 `health`와 `prometheus`만 연다.
  - Grafana는 로그인 없이 쓰도록 익명 Admin을 켰다. 대신 `127.0.0.1`에만 바인딩해 같은 PC에서만 접속할 수 있게 했다.
