# entry.requested 발행 실패 시 대기 화면이 멈춤

## 증상

- 브로커 장애 중에 입장을 요청하면 API는 202(접수)를 응답하고 대기 화면이 뜬다. 그런데 순번이 줄지 않은 채 멈추고, "다시 줄 서기"도 나타나지 않는다. 대기 줄 키 TTL(1시간)이 지나야 줄에서 사라진다.
- DLT 재투입 발행이 실패할 때도 같은 일이 생긴다. 재투입 실패는 에러 로그로만 남고, 요청은 줄에 남은 채 끝난다.
- outbox 작업 중에 "이 토픽은 유실돼도 회복된다"는 근거를 코드로 확인하다가 발견했다.

## 원인

- `EntryRequestProducer.send()`는 `KafkaTemplate.send()`를 비동기로 호출하고, 실패는 `whenComplete`에서 에러 로그로만 남겼다.
- 요청은 발행보다 먼저 Redis 대기 줄(ZSET)에 선다. 그래서 발행에 실패하면 줄에는 있지만 Kafka에는 없는 요청이 생긴다. Queue Worker가 이 요청을 꺼낼 일이 없어 순번이 영원히 줄지 않는다.
- 대기 화면의 "다시 줄 서기"는 상태가 `FAILED`일 때만 나오는데, 이 경로에서는 아무도 실패로 표시하지 않았다.

## 해결

- `EntryRequestProducer.send()`가 발행 결과 future를 반환한다. `EntryServiceImpl`은 실패하면(콜백, 또는 `send()` 호출 자체의 예외) 요청을 줄에서 빼고 `entry:failed:{requestId}`로 표시한다. DLT 재투입도 같은 경로를 탄다. 상태 조회가 `FAILED`를 반환하므로 대기 화면이 1초 폴링으로 바로 "다시 줄 서기"를 안내한다.
- 대기 화면은 입장 요청 자체가 실패했을 때(네트워크 오류 등)도 오류 문구와 함께 "다시 줄 서기" 버튼을 보여준다. 전에는 문구만 있고 다시 시도할 방법이 없었다.
- 처음에는 브로커 확인을 기다린 뒤 202를 주고, 실패하면 503을 주는 동기 방식으로 고쳤다. 그런데 이 PC에서 동시 50건을 보내 보니 p50이 15ms(브로커 미사용 기준선)에서 220ms로 늘었다. 확인을 기다리는 10~20ms 동안 요청 스레드가 묶여 줄이 밀린 것이다. 입장 요청은 순간 트래픽을 싸게 받아내는 구간이라, 응답은 비동기로 두고 실패만 콜백으로 처리하는 방식으로 바꿨다.
- 남는 한계:
  - 브로커가 메시지를 받는 도중에 끊기면, Producer가 `delivery.timeout.ms`(기본 120초)까지 재시도한 뒤에야 실패를 알린다. 그동안 사용자는 대기 화면에 머문다.
  - 브로커가 처음부터 없으면 `max.block.ms`(5초) 뒤에 바로 실패로 표시된다.
  - 실패로 표시된 뒤 메시지가 늦게 도착해 토큰이 발급되면, 상태 조회가 토큰을 먼저 확인하므로 `GRANTED`로 정상 입장한다.
