# 좌석 Redis 락/토큰 표시 정리가 DB 커밋과 어긋남

## 증상

- 좌석 선점이 커밋 단계에서 실패하면(DB 장애, 커밋 시 제약 위반 등) DB는 AVAILABLE인데 Redis 좌석 락과 "토큰당 1석" 표시가 5분 동안 남는다. 그 좌석은 아무도 잡을 수 없고, 그 사용자도 다른 좌석을 잡을 수 없다.
- 확정/해제는 Redis 표시와 락을 먼저 지우고 커밋한다. 커밋이 실패하면 좌석은 HELD로 남는데 표시는 지워져, 같은 토큰으로 다른 좌석을 추가로 잡을 수 있다.
- 바깥 트랜잭션에서 서비스 메서드를 호출한 뒤 롤백시키는 테스트로 재현했다(`SeatRedisTransactionSyncTest`). 수정 전 코드에서 선점·확정 테스트가 실패했다.

## 원인

- 선점은 메서드 안의 try/catch에서만 락을 풀었다. 메서드가 정상 반환한 뒤 커밋 단계에서 나는 실패는 이 catch에 잡히지 않는다.
- 확정/해제는 Redis 정리를 메서드 본문에서 바로 실행했다. Redis는 DB 트랜잭션에 참여하지 않으므로 롤백되지 않는다.

## 해결

- 선점: 락과 토큰 표시를 잡은 직후 `TransactionSynchronization.afterCompletion`을 등록한다. 트랜잭션이 커밋되지 않으면(본문 예외든 커밋 실패든) 락과 표시를 푼다. 기존 try/catch 해제 코드는 이 하나로 합쳤다.
- 확정/해제: Redis 정리(토큰 표시 삭제, 좌석 락 해제)를 `afterCommit`으로 옮겼다. DB 변경이 실제로 커밋된 뒤에만 정리한다.
- 확정은 결제 서비스의 `TransactionTemplate` 안에서 호출되므로, 결제 기록과 outbox까지 포함한 바깥 트랜잭션이 커밋된 뒤에 정리된다.
